# 评测口径

`cases.json` 是 60 条明确标注的合成案例：城市、轻户外、锁定三家族共 30 开发；室内家族 10 验证；缺失条件、版本冲突两家族共 20 保留。

生成后记录 SHA256。它是可复现的工程数据集，不代表真实游客分布，不能用状态匹配率宣称用户满意度或生产成功率。作者知道案例结构，不属于第三方盲测；一旦用于修改实现，相关结果只能叫回归结果。

- `regression`：60 条运行真实 LangGraph、MySQL 检查点和业务提交，使用固定合成平台数据、不调用模型。
- `local-model-smoke`：相同合成输入，用已安装的本地模型运行纯模型／单 Agent／按需多 Agent，保存原始输出和工具过程。只是连通与能力冒烟，不是最终效果评测。
- `cloud-heldout`：需要实际模型 Key；对保留案例运行三策略。人工补充信息案例的首轮终态为 waiting_input，不伪造用户回答。

三策略的输出形式不同：纯模型是未经工具核验的文本草案；另两条是结构化计划。不得把“纯模型没有结构化天数”直接当作业务失败，必须另外人工核对约束和无依据陈述。

原始报告记录任务 ID、输入集哈希、模型、状态、模型／工具次数、Token 使用、延迟和 Trace。模型没有返回用量时记录未知，不按 0 Token 计费。费用要在确认地域、模型价格和账单后计算。冷启动和预热分开记录，人工等待不计推理时间。

后续人工逐例评阅维度：日期人数与预算约束、来源覆盖、地点及交通真实性、开放预约条件、锁定保留、适当追问、修改影响、无依据陈述和实际可用性。任何“提升比例”必须同时给出 baseline、相同样本、配置和原始结果。
