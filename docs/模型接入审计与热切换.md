# 模型接入审计与热切换

审计日期：2026-11-21。项目路径 `travel_agent` 是 `TripPal` 的符号链接。结论基于代码与本机配置，不把配置存在当成服务已经启动、模型已下载或云端已联调。

## 现状与模型清单

**不是全部为本地模型。** 本机 `config.local.json` 当前选中 `current`，其对话配置为 `openai` + `http://127.0.0.1:11434/v1` + `qwen3.5:9b`，实际由 Ollama 原生驱动执行。`openai` 在此项目的旧语义是兼容协议，并不代表 OpenAI 官方云端。

| 已接入本地模型 | 当前配置状态 | 调用入口与用途 |
|---|---|---|
| `qwen3.5:9b` | 当前对话配置；`current` 与 `local_qwen` 是同一模型的不同配置名 | `agent/harness.py:model()` → `models/gateway.py:chat_model()` → `ChatOllama`；`agent/graph.py` 工具调用与流式答复；`agent/structured.py:generate()` 需求提取、任务分派、规划结构化输出 |
| `BAAI/bge-small-zh-v1.5` | 默认启用的本地向量模型，CPU；`embedding_local_only=true` 只读本机缓存 | `knowledge.py:embed()` → `embedder()` → `models/gateway.py:local_model('embedding')` → `SentenceTransformer.encode()`；文档入库、混合检索和 `research_cache.py` 语义缓存共用 |
| `BAAI/bge-reranker-base` | 已实现，默认 `reranker_enabled=false`；并非每次检索均执行 | `knowledge.py:search()` → `rerank()` → `reranker()` → `models/gateway.py:local_model('rerank')` → `CrossEncoder.predict()` |

代码、旧验收文档和升级脚本也提到 `qwen3:4b`、`qwen3:4b-instruct`、`qwen3:8b`，属于历史模型/迁移对象，不是当前独立启用的模型入口。它们若仍安装，可以通过修改模型名称复用 Ollama 入口。机器缓存中其他模型不因此视为本项目已集成。

云端入口已存在：

- 对话/结构化：OpenAI 兼容协议、Gemini 原生 SDK；内置供应商表含 OpenRouter、百炼、OpenAI、SiliconFlow、DeepSeek、Gemini，真实可用性取决于账号、端点和模型能力。
- 视觉：`vision.py:recognize()` → `gateway.post_chat('vision')`，默认模型 `qwen-vl-max-latest`，原默认开关关闭。本次也补齐显式 `ollama` 视觉槽位，经本地 `/v1/chat/completions` 调用；模型必须实际支持图片。
- ASR：`voice.py:transcribe()` → `gateway.post_chat('asr')`，默认 `qwen3-asr-flash`；TTS：`voice.py:synthesize()` → `gateway.post_json('tts')`，默认 `qwen3-tts-flash`，两者默认关闭。
- `fixture` / `synthetic` 是显式演示数据，不是本地模型。没有云端失败后自动改用其他供应商的隐式回退。

## 本次实现与模块职责

保留并完善项目已有的 `models` 抽象，业务仍调用原入口，未创建另一套平行 SDK 层。

| 模块 | 本次变更 |
|---|---|
| `config.py` | 新增 `model_auto_reload`、`model_settings_snapshot()`、`reload_model_settings()`、`model_reload_status()`；锁内校验，原子替换模型字段；保留 settings 对象身份；错误保留旧配置 |
| `models/registry.py` | 对配置快照解析各能力；修复不同供应商槽位误用主模型端点、凭证、模型名称及结构化方式；不再静默忽略 embedding/rerank 槽位覆盖；补齐 Ollama 视觉路由 |
| `models/gateway.py` | SDK 构造固定使用同一配置快照；HTTP 接口接收已解析 spec，避免请求模型名与端点在切换时混配；集中本地检索模型的加载缓存 |
| `agent/harness.py`、`agent/structured.py` | 保留原 model 入口并允许传快照；一次结构化生成及其纠正重试固定使用同一模型配置与输出方式 |
| `knowledge.py` | 原 embedder/reranker 入口保留，底层加载委托统一网关 |
| `vision.py`、`voice.py` | 把组装请求时的 spec 传入网关，使模型、鉴权和地址保持一致 |
| `config.models.example.json` | 展示 profile、独立本地兼容端点、热更新开关；本地样例显式关闭视觉/语音外部通道 |
| `tests/test_model_reload.py` | 新增真实文件编辑、切换、回滚、凭证、优先级、索引变更拒绝等离线回归测试 |

## 配置字段与切换方式

直接编辑根目录 `config.local.json`，无需命令行参数。完整示例见 `config.models.example.json`；请合并字段，保留数据库、地图与业务配置，不要用示例覆盖私密配置。

```json
{
  "model_auto_reload": true,
  "active_model_profile": "local",
  "model_profiles": {
    "local": {
      "model_provider": "ollama",
      "model_name": "qwen3.5:9b",
      "model_base_url": "http://127.0.0.1:11434",
      "model_enabled": true,
      "model_slots": {
        "vision": {"enabled": false},
        "asr": {"enabled": false},
        "tts": {"enabled": false}
      }
    },
    "cloud": {
      "model_provider": "deepseek",
      "model_name": "deepseek-chat",
      "model_enabled": true
    }
  }
}
```

为云端 profile 单独填写 `model_api_key`，或使用该供应商的 `key_env`（例如 `DEEPSEEK_API_KEY`）。将 `active_model_profile` 改为 `cloud` 即切换，改回 `local` 即恢复本地。更换 Ollama 模型只需修改对应 profile 的 `model_name`；不用改业务代码。示例模型名不保证你的账号或本机具备该模型。

| 字段 | 含义 |
|---|---|
| `model_auto_reload` | 新增，默认 true；每次模型解析检查文件元数据；false 时仅显式重载或重启生效 |
| `active_model_profile` / `model_profiles` | 选择整套模型配置；空名称继续使用旧版平铺字段 |
| `model_provider` / `model_name` / `model_base_url` / `model_api_key` | 默认对话供应商、模型、地址、凭证；`gemini_base_url` 用于原生 Gemini 自定义端点 |
| `model_enabled` / `model_timeout` / `model_output_tokens` / `model_context_tokens` / `model_reasoning_effort` | 启用、超时、输出预算、Ollama 上下文及推理选项；Ollama 保留原行为 `reasoning=false` |
| `structured_output_method` | auto / json_schema / function_calling；Ollama 保持 JSON Schema |
| `model_providers` | 注册或覆盖供应商：protocol、base_url、default_model、key_env、requires_key、capabilities、structured_method、extra_headers、extra_body、chat_path |
| `model_slots` | 为 chat / structured / vision / asr / tts 分配 provider、model、base_url、api_key、enabled、timeout、structured_method、extra_headers、extra_body；`use_main_key` 仅允许同域共享主 Key |
| `vision_*` / `voice_*` / `asr_model` / `tts_model` | 保留原字段，并允许写入 profile；顶层独立视觉/语音配置仍可共用 |
| `embedding_model` / `embedding_local_only` / `reranker_model` / `reranker_enabled` | 保留本地检索模型配置；本次不提供云端向量/重排协议适配，修改后按重启/索引流程迁移 |

`model_providers` 可注册任意遵守既有协议的本地或云端服务。例：`{"protocol":"openai","base_url":"http://127.0.0.1:8000/v1","requires_key":false}`，再把 profile 的 `model_provider` 指向该注册名。这样本地兼容服务不会被强制改用 Ollama 驱动。新的非兼容协议需要新增适配器，单靠更换 URL 无法实现协议转换。

配置优先级为默认值 < 平铺配置 < 选中 profile < `TRAVEL_*` 环境覆盖；槽位字段对该能力最终覆盖上述默认值。`TRAVEL_ACTIVE_MODEL_PROFILE` 在应用 profile 前读取。为兼容旧配置，顶层 `model_slots` 仍作为共享默认值；profile 若声明 `model_slots`，会整体替换共享槽位。推荐把供应商专属槽位写入对应 profile，完全本地的 profile 显式关闭外部槽位。每次热加载从文件重新构建，未选中 profile 的槽位不会残留。token/timeout 等共享平铺参数保留，profile 可覆盖。

## 热更新边界与兼容性

- **加载时机**：API、Celery worker、MCP 进程各自在下一次模型入口解析时检查同一配置文件，无需后台线程。模型状态接口 `GET /api/v1/models` 也会触发检查。
- **请求边界**：已开始的流式请求继续旧客户端；下一次构造模型的调用使用新配置。一项长任务的不同阶段可能使用不同模型；一次结构化生成及其最多一次纠正使用相同快照。不是整个任务或整个集群同时切换。
- **多进程**：每个进程独立加载，不广播；必须让 API 与所有 worker 看到更新后的同一文件。容器中若配置复制进镜像、单文件绑定挂载未反映原子替换或文件路径不共享，需要更新挂载/重建容器。推荐共享目录挂载并原子替换 JSON。
- **失败行为**：非法 JSON、无效供应商、非法槽位、非正预算等会拒绝发布，继续使用上次配置。无效文件只尝试一次，修正并保存后重新加载。状态包含 reload.generation、reload.error、reload.restart_required，不输出验证时包含凭证的输入内容。
- **就绪不等于联网验证**：重载只校验配置，不调用收费模型。缺少 Key 可显示 needs_key，认证失败、模型不存在或不支持工具时仍由现有错误处理报告，不自动切换服务。
- **检索模型**：已有索引与语义缓存的向量维度固定为 512。换 embedding 即使维度相同也改变向量空间，必须重建文档索引并清理/更换语义缓存索引；维度不同还需修改两个索引 mapping。embedding_model、embedding_local_only、reranker_model 变化会拒绝整次热更新。重排模型本身不用重建文档向量，但需重启以重载进程内模型。reranker_enabled 当前同样需重启。
- **其他配置**：数据库连接、Redis、监听端口等不热应用，状态列出 restart_required；环境变量必须存在于实际运行的进程，另一个终端 export 不会改变旧进程环境。SDK/协议适配器代码变更需重启。
- **语音协议**：ASR 保持现有音频 chat/completions 请求结构，TTS 保持百炼原生结构与下载域名限制；不能把任意厂商的 `/audio/speech` 地址当成等价替换。Gemini 视觉原生协议也未适配；通过兼容接口或显式独立视觉供应商使用。
- 本地对话不等于整个应用完全离线；地图、搜索、业务供应商另有网络调用。本地 profile 若要禁止云端模型，还需显式关闭 vision/asr/tts 或为其配置支持的本地服务。
- `settings` 对象身份、旧版 `openai + localhost:11434/v1` 识别、业务入口、fixture 标记和对外接口保留；本次未改动真实 `config.local.json` 或主动切换当前模型。

进程内显式触发方式（不是在另一个 Python 进程中运行）：

```python
from travel_agent.config import reload_model_settings
reload_model_settings()
```

未新增公开的配置写入 HTTP 接口。运营时编辑受控配置文件即可，状态接口只读。

## 迁移与验证

1. 部署代码并一次性重启 API、所有 worker/MCP 进程；旧进程尚无热更新代码。
2. 备份配置；保留 current/旧平铺配置。把各供应商凭证写入各自 profile，或指定独立环境变量；若共享槽位绑定了特定供应商，建议移入相应 profile；既有顶层共享槽位仍然兼容。
3. 安装所选本地模型或准备云端模型权限；对话、工具调用、结构化输出、视觉分别验证能力，不能只凭普通文本回复验收。
4. 保存配置，查看 `/api/v1/models` 的 profile、slot 地址、模型、ready/needs_key、reload.generation 和 error。切换本地 A → 本地 B → 云端 A → 云端 B → 本地，检查真实请求目标和返回来源。
5. 验证工具绑定、流式分块、Schema 有界纠正、错误分类、截图确认流程、音频处理以及 fixture 行为。模拟无效 JSON、错误 profile、缺 Key、HTTP 401/429/超时，确认不会误用上一家 Key 或暗中改供应商。
6. 在流式输出中途切换：旧流应完成，新调用应采用新模型；分别检查 API 与 worker 的配置状态。大规模切换先排空任务，避免一项任务跨模型阶段。
7. 换向量模型按停写、建立新索引/新缓存索引、全量重新编码、验证检索效果、更新配置并重启的流程执行；保留旧索引用于回退。
