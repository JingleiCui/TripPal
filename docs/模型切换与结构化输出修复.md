# 模型切换与结构化输出修复

## 修改一个配置名即可切换

编辑项目根目录 `config.local.json` 的 `active_model_profile`，保存后先运行 `stop_project.py`，再运行 `run_project.py`，使 API 和 worker 一起加载新配置。

| 配置名 | 用途 |
|---|---|
| `current` | 本轮开始时的现有配置，模型和凭证原样保留 |
| `local_qwen` | 本机 Ollama 的 qwen3.5:9b，原生客户端，无云端计费 |
| `google_gemini` | Google 官方 Gemini；先在对应配置内填写 Key 和账号实际可用的模型名 |
| `bailian_qwen` | 百炼 OpenAI 兼容接口；先在该配置内填写百炼 Key |

例如：`"active_model_profile": "local_qwen"`。全部样例见 `config.models.example.json`，样例不保存真实密钥。凭证只填写在私密的 `config.local.json` → `model_profiles` → 对应配置中。

切换配置不会继承另一家提供者的密钥。选不存在的名称会明确报错，不悄悄换模型。兼容旧版平铺配置：`active_model_profile` 为空时继续使用旧字段。优先级为默认值、本机平铺字段、选中配置、`TRAVEL_` 环境覆盖。

## 并不都是 OpenAI 协议

- `model_provider: openai`：使用 OpenAI 兼容接口，通常是 `/v1` 或百炼 `/compatible-mode/v1`。兼容基础对话不等于所有工具调用、JSON Schema 和流式字段都兼容，换平台后仍须实际验证。
- `model_provider: ollama`：使用 Ollama 原生客户端，地址通常为 `http://127.0.0.1:11434`。保留对旧版 localhost:11434/v1 配置的识别，但执行时走原生客户端。
- `model_provider: gemini`：使用 Google 原生客户端，Key 来自 Google AI Studio；不把 Google Key 发给 OpenAI 兼容接口。

`structured_output_method` 默认 `auto`：Ollama/Gemini 使用 JSON Schema，其他 OpenAI 兼容服务使用 Function Calling。只有确认平台支持时才显式改为 `json_schema` 或 `function_calling`。不支持的能力不使用假结果填补。

## 本轮修复

原来的编排只依赖 Function Calling；解析失败发生在业务纠正逻辑之外，因此立即中止。现在需求提取、任务分派和行程编排统一使用有界结构化生成，字段校验与业务校验共用最多两次尝试。实际业务工具仍正常使用 Tool Calling。

诊断记录输出结束原因、字符长度、工具调用数量、字段错误位置与类型，不保存原始隐藏思考或密钥。错误继续使用 `code: schema`，同时给出阶段和具体原因。

执行事件增加批次标识。重试从 LangGraph 失败节点恢复；历史事件按批次折叠，顶部错误使用当前任务结果，不把历史地区错误当成新错误。

## 验证口径

原始 9 次验证：单城市 3 次完成、多城市 3 次完成；锁定场景的 3 次被时间约束拒绝。检查后发现验证脚本手工构造的旧行程不可达，因此不能算作三个有效的修改用例，也不能删除或改写这些失败记录。原始结果保存在 `reports/schema-model-verification.json`。

修正后的锁定场景使用真实高德交通先生成可行旧行程，再由当前 9B 模型执行修改，逐次结果另存 `reports/schema-model-locked-valid-baseline.json`。这些是本机小样本功能验证，不是总体成功率、生产 P95 或独立盲测。
