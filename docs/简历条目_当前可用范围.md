项目经历（可直接复制）

TripPal｜旅伴：AI 旅行规划与行程管理平台

项目介绍：面向国内自由行用户，提供旅行需求收集、行程推荐、地图探索、每日吃住行安排和路书导出，支持通过自然语言持续调整旅行计划。

技术栈：Python、FastAPI、LangChain、LangGraph、MySQL、Redis、Celery、Elasticsearch、React、TypeScript。

负责内容：

1）旅行规划：完成目的地、日期、人数、预算和偏好收集，结合景点、交通、天气与住宿查询生成单城市、多城市的每日行程，支持候选方案比较和选择。

2）行程调整：支持通过对话修改出行条件和每日安排，保留用户锁定的地点与时间；提供餐厅替换、住宿选择和交通方式调整，并展示对应路线、已知花费及待核实事项。

3）地点探索与攻略检索：完成按城市、分类和关键词查找景点、美食及住宿的功能，支持地图联动、滚动加载和收藏；支持上传个人攻略，检索相关内容并查看原文位置。

4）行程管理与交付：完成账户、行程保存和历史版本管理，支持成员协作、只读分享及分享撤销，提供每日路书预览和 PDF、Markdown 导出。

5）功能验证：构建 60 条合成业务回归案例，覆盖条件补全、锁定修改和版本冲突等场景；对单城市、多城市及可行基线上的锁定修改各完成 3 次本地模型真实流程验证。

架构思维落实在三条边界：候选选择与事实核验分开，用户条件与生成结果分开，执行进度与最终提交分开。讲述时用“用户继续改要求”“已经查到资料但编排失败”“旧任务晚返回”三个业务例子展开。

**架构判断：面试开场 60—90 秒**

我做的是一个需要持续修改、需要查询外部事实的旅行规划产品。用户说“少走路，但必须保留某天下午的一个景点”，系统既要理解这次修改，又要保留之前确认的条件，还要重新核对路线能否衔接。

我把系统拆成需求状态、规划编排、工具适配、执行治理和业务提交几个职责。模型理解需求并选择候选；工具提供地点、交通和资料事实；业务代码检查城市、日期、锁定时间及路线约束；最终写入还要核对权限和行程版本。调查结果与执行进度放入图状态，失败时从检查点继续。

这种分工把模型输出的不确定性限制在可校验的边界内。Harness 决定某次调用能否继续，任务租约决定哪个执行器可以推进，行程版本决定结果能否提交。三者处理不同问题，不能只靠一个检查点解决。

**工具、上下文与 Harness 的真实实现范围**

| 模块 | 当前实际实现 | 对应问题 |
|---|---|---|
| Tool / Provider | LangChain 类型工具；高德地点、路线与天气，美团查询，私人资料检索；输入约束、来源字段、错误分类，缺失事实保持未知 | 将外部事实与模型自由输出分开，区分不可用、空结果和格式错误 |
| Context | 槽位合并；显式目标与约束；确认偏好、待办、旧地点及锁定信息；按任务注入；调查结果保存在图状态 | 本轮未提及不等于取消；避免重新从完整聊天记录推导全部状态 |
| Harness | 工具能力过滤；调用前后检查任务状态、租约和编辑权限；模型/工具次数及执行时间限制；持久事件、耗时与用量；恢复时延续已有调用计数 | 限制循环和越权，及时阻止被取消或接管的执行器继续推进，定位失败阶段 |
| Durable execution | MySQL queued 任务、派发器、Redis / Celery、租约与心跳；图检查点；提交时权限和基准版本检查 | 区分投递、执行、图恢复和业务提交，避免恢复后的旧结果覆盖新版本 |
| Structured output | 按提供者选择 JSON Schema / Function Calling；字段和业务校验共用两次尝试上限；脱敏诊断 | 模型能聊天不等于能稳定输出结构，重试必须有范围和错误反馈 |

说明：上下文实现以结构化状态和固定长度控制为主，并未实现自学习长期记忆、复杂记忆分层或自适应语义压缩；Harness 约束项目规划执行链路，不是整个操作系统的代码沙箱。恢复机制也不保证外部 API 或模型推理恰好调用一次。

**问题—方案—结果：最值得准备的实战故事**

问题：本地 qwen3.5:9b 已完成部分调查，但在行程编排的结构化输出阶段失败。原实现对提供者使用统一输出方式，解析错误又绕过后面的业务纠正，导致无法定位具体失败，也不能合理复用已经完成的调查。

方案：按提供者适配原生结构化输出；统一检查 JSON / 字段与候选业务约束，允许反馈错误后纠正一次；补充输出结束原因、字段错误、调用批次等诊断；通过原任务检查点恢复编排节点。

结果：真实模型验证中，单城、多城及可行锁定修改各完成 3 次；原失败任务恢复完成，未重复主 Agent、地点和天气调查。最初使用不可行旧行程的 3 次失败单独保留，作为约束拒绝案例。
