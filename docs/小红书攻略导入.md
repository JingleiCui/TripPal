# 小红书攻略导入

在“探索发现”的 AI 助手中打开“小红书攻略导入”，或直接在对话框粘贴小红书分享文案/链接并发送。

## 可用流程

1. 粘贴分享文案或笔记链接，系统在后台尝试读取正文和配图。支持小红书短链接，以及官方页面跳转到 rednote.com。
2. 链接未能读取或只读到预览时，明确显示缺口。可以保留原链接，粘贴正文并批量上传配图。
3. 配图先分类：攻略文字图完整转写；纯照片、无文字图、只有相机参数/品牌水印的图跳过。拿不准时保留识别，跳过图也可点击“仍然识别这张图片”。
4. 长图按原分辨率分块，转写内容不会沿用旧截图接口的 800 字摘要限制。原图、逐图文字和出处可展开核对；失败的图片可以单独重试。
5. 正文和配图解析完成后，自动把整篇笔记正文、配图转写与候选要点交给 AI 助手继续回答，不需要逐项勾选确认。面板仍可展开查看来源；必要时可编辑候选文字或点“重新交给助手”。
6. 有来源的地点经高德匹配后显示在右侧地图。重名或不明确时指定城市并选择实际查询候选；模型不生成坐标。地图预览及导入本身均不提交正式行程。

## 首次登录配置（仅一次）

如果浏览器兜底仍落到登录/风控页，界面会提示先完成一次登录配置。在项目根目录运行：

```bash
node frontend/xhs-login-setup.mjs
```

会打开一个 Chrome 窗口；在窗口里登录小红书后关闭它即可。登录态保存在 `~/.config/tripal/xhs-browser-profile`，后续解析自动复用，不用每次重新登录，也不用手填 Cookie。只有登录态过期或被平台注销时才需要重新运行该命令。

笔记作者的价格、营业时间、日期属于待核实参考，不自动变成用户的出游日期或预算。对话读取整篇笔记正文、配图转写与候选要点并保存附件引用；后台执行及提交前再次检查资料归属和是否变化。

## 读取边界

默认先用轻量 HTTP 读取公开页面。如果只读到可关闭的登录弹层，会用无头浏览器打开同一页面，关闭弹层后从页面状态/DOM 提取正文和配图（`note_browser_fallback: true`）。如果页面要求真正的登录态，才需要显式启用本人会话：在 `config.local.json` 中设置 `note_login_enabled: true`，并把浏览器复制的 Cookie 请求头写入 `note_cookie_file`。用途仅限个人助手读取用户主动提交、本人有权查看的笔记，不做批量抓取、不转发、不商业化。

会话 Cookie 只从本地文件读取，文件权限必须为仅本人可读写（`chmod 600`）；只发送给 `note_cookie_hosts` 列出的笔记域名，绝不发送给图片 CDN，也不写入数据库、附件正文或日志。未配置本人会话时，浏览器兜底不携带任何账号凭证。Cookie 过期后重新从浏览器复制即可。若链接最终跳转到 `rednote.com`，且你的会话属于该站点，需要把 `rednote.com` / `www.rednote.com` 加入 `note_cookie_hosts`。

不保证每个链接都能读取：链接失效、登录态过期、访问限制、正文缺失都会显示对应状态，不会把分享标题或网页预览当成完整笔记。早期匿名读取的示例中，官方页面跳转到 rednote.com 后返回登录页，未获得正文或图片；开启本人会话后由浏览器同款登录态重新读取。

本机代理可能返回 198.18/15 合成 DNS 地址。默认对这种地址向固定的 HTTPS 公共 DNS 服务查询官方域名，再只连接校验过的公网 IP、验证 TLS 域名；回环、内网地址和非允许域名仍拒绝访问。配置 `note_public_dns_fallback: false` 可关闭这项兼容措施，需重启服务。DNS 查询仅包含域名，不包含笔记链接和正文。

第一版不处理评论和视频，也不支持手机系统分享直达。正文最大 20 万字符；每篇最多 20 张图片，单张 5 MB、总计 50 MB。超过限制明确拒绝或标记未完成，不静默省略。极长图片、模糊文字和达到时间预算的任务可分批补充、重试及人工核对。

## 部署与数据

无新增 SQL 表或迁移：复用 Attachment 的 `travel_note` 类型及 JSON 状态。原图保存在 `data/note-imports/<owner>/<id>/`，需登录且属于本人才能读取；支持删除、账号数据导出及注销后的持久清理。运行中的任务带租约和检查点；Redis 暂不可用时保留 SQL 排队记录，由 API 调度器重新投递。

本次代码需要重启 API 和 worker。运行 `run_project.py` 会同时启动规划 worker 和独立的笔记 worker；容器部署增加 notes 服务。笔记专用进程命令：

```bash
PYTHONPATH=backend .venv/bin/python -m celery -A travel_agent.notes.worker:celery worker -Q note_imports --pool=solo --concurrency=1 --hostname=travel-notes@%h
```

注意：独立队列不占用规划 worker，但本地图片和对话仍共用 Ollama，计算繁忙时会竞争模型推理资源。任务每步持久化，30 分钟预算到达后保留结果并允许重试；不是无限后台循环。

## 验收

```bash
.venv/bin/python -m pytest backend/tests/unit/test_notes.py backend/tests/integration/test_notes.py -q
.venv/bin/python scripts/validation/notes.py
npm run test:e2e --prefix frontend -- note-import.spec.ts
```

真实模型验收脚本使用独立评测数据库、Redis DB 12/13，先确认 chat/structured/vision 为本地 Ollama，真实执行文字图转写、纯图及水印跳过、来源抽取、地点匹配、确认，再启动隔离笔记 worker 检查异步队列。输入为明确标记的合成样例，不将其当成真实小红书笔记读取成功的证据。输出位于 `reports/note-import-real-local.json`。

接口：`POST /api/v1/note-imports`（multipart：share_text/body_text/files[]）、GET 列表/详情、POST sources/retry/confirm、POST facts/{fact_id}/place，以及受权限保护的原图 GET 和 DELETE。对话 turns 与 RunRequest 增加可选 `attachment_ids`，旧调用省略该字段即可。
