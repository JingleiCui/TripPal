# 部署与运维

## 本机

运行 `run_project.py` 启动专用容器、迁移、检查点、构建前端、worker 和 API。启动不会重置资料。容器数据在 `travel-agent_*` 专用卷，原文在 `data/uploads`。

数据库 MySQL 8.4 限制 1 GiB，Redis 256 MiB，ES 1536 MiB／JVM 512 MiB；服务端口只绑定 127.0.0.1。默认一个 solo worker，适合 Mac 本地观察和单模型配额，不声称支持高并发生产负载。线程及推理并发应在压测后调整。

开发库密码只适用于本机，**不作为服务器默认密码**。服务器部署必须使用独立密码和只授予应用库权限的账号，通过环境或私密配置覆盖连接。MySQL root 仅用于本机迁移演练和备份脚本，Web 请求不使用 root。

## 常见问题

- 8808 已占用：如果是本项目，直接访问已有页面；否则自行检查端口。不会自动杀进程。
- Docker 未运行：先启动 Docker Desktop。Docker Hub 网络失败时不要关闭证书验证；可使用可访问的镜像来源，但要核对内容 digest。
- Redis noeviction 达上限：排查队列积压与缓存 TTL，扩容或清理明确可丢弃缓存，不能直接 flush 任务库。
- queued 不执行：检查 worker、Redis 1 号库及 API 派发线程。任务仍在 MySQL，服务恢复后会再次投递。
- worker 崩溃：等待租约到期，重新派发；旧 token 在工具边界和最终事务前被拒绝。只读查询可能重复，业务版本不能重复提交。
- 模型不可用：行程回看、导出、资料和账号页面仍可使用；新真实规划显示失败或待配置。
- ES 不可用：已有行程可查看，检索显示故障，不返回假资料。
- BGE 冷启动：首次加载与预热分开测；使用本机缓存、CPU 两线程，避免占用 GPU 推理资源。

## 备份与恢复演练

在项目环境运行 `scripts/backup.py`。它开启短暂维护标志、停止新写入与派发、等待正在执行的任务，联合备份数据库及原文，并生成校验清单。正常退出移除维护标志。

把脚本顶部 MODE 改为 `verify` 可恢复最新备份到**独立的 `travel_agent_restore` 数据库**并核对原文归档哈希。它不覆盖当前业务库。真实恢复时需要停服务、验证备份版本、使用新的连接配置启动，并从原文重建 ES；不要把恢复演练当作已经演练过所有生产灾难。

## 服务器交付方式

本项目提供的是本机验收及可迁移源码，不自动购买或发布公网服务。服务器安装 Python 3.11、Node、Docker，使用锁定依赖和构建产物，分别启动 API 与 worker。用 Nginx 将 HTTPS 请求代理到回环地址 8808，SSE 路径关闭缓冲、读超时大于任务预算，保留 `Last-Event-ID`。

公开部署必须：使用 HTTPS、`cookie_secure=true`、真实账号策略和独立私密配置，关闭 fixture 能力，禁止公开 MySQL／Redis／ES 端口，关闭或限制 API 文档与管理入口；不要公开本机备份目录。公开注册应增加验证与运营限制，当前本机账号策略不能直接当作开放互联网账号系统。

仓库提供 `Dockerfile`、`compose.server.yaml`、`.env.server.example` 和 Nginx 配置示例。服务器使用独立 Compose 项目和数据卷，先把环境示例复制为 `.env.server` 并填写独立密码；完整连接 URL 中的密码需要 URL 编码。MySQL／Redis／ES 没有发布公网端口。API Cookie 为 Secure，需要通过 HTTPS 访问。

服务器容器构建、HTTPS 与公网连通未在真实服务器验收，不能把模板存在写成已经完成生产部署。本机已经验收的路径是 Python API／worker＋数据库容器。服务器需要预置可信 BGE 权重或允许首轮下载；美团还需给 worker 安全挂载官方 Token 配置。

多 worker 部署仍以 MySQL token 和行程版本作为提交门禁；不使用 Redis 缓存状态判断最终业务完成。回滚应用前核对数据库迁移兼容性，默认不执行破坏性 downgrade。
