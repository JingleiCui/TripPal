# 本地与云端分工建议

记录日期：2026-11-22。当前应用仍选择 `local_complete`，全部模型槽位均在本机运行，没有为此建议调用云端模型 API。

## 根据本机实测决定

修复后的真实地点数据验证：最后一次完整脚本中，单城规划约 54.7 秒，多城约 47.0 秒，保留锁定地点修改约 46.0 秒，每个场景执行一次；此前同样场景约 35–37 秒。截图识别两次约 28.4 秒。这些是本机当次端到端/请求耗时，不是吞吐或质量基准；不同输入、模型冷热状态、外部数据服务和并发会改变时间。

| 能力槽位 | 建议 | 理由 |
|---|---|---|
| `chat`、`structured` | 对交互等待敏感时优先考虑云端 | 规划的多轮工具调用和结构化生成占用本地推理时间；可以一起切换，减少模型间行为差异 |
| `vision` | 暂时本地；如果截图是高频入口，再单独比较云端视觉 | 本机实测约 28 秒，值得单独优化；需要实际截图验证提取准确率，不能仅看文字对话速度 |
| `embedding`、`rerank` | 继续本地 BGE | 已通过实际检索验证；切云端增加数据传输与索引迁移成本，当前不是优先改造对象 |
| `asr`、`tts` | 先保留本地 Whisper/系统中文声音 | 已通过朗读→转写往返，不增加云端音频调用；需要更自然声音、跨平台或大量并发时再评估云端语音 |

优先考虑把对话与结构化输出接到 **Qwen3.8-Flash (`qwen3.8-flash`)**。官网确认该模型支持 Function Calling、结构化输出、上下文缓存和 OpenAI 兼容调用，符合本项目的主要接口需求；上下文为 1,000,000，最大输出为 131,072 tokens。项目实际仍应保留较小输出预算，而非使用规格上限。[官方模型说明](https://help.aliyun.com/en/model-studio/qwen3-8-flash)

该模型支持文本、图像和视频输入、文本输出，不负责语音识别或语音合成；也不能把它当成经过本项目验收的专用精确 OCR。此处只推荐先用于 chat/structured。与全本地相比，它会把请求提示词及包含的候选/检索摘要发送给供应商；云端真实延迟和业务通过率尚未在本项目测量，不能承诺一定快多少。

官网当前列出的中国北京原价为输入 ¥0.8/百万 tokens、输出 ¥2.7/百万 tokens，缓存输入 ¥0.1/百万 tokens；区域与部署方式可能不同，接入时再确认账号实际可用范围和价格。[官方价格及地域表](https://help.aliyun.com/en/model-studio/qwen3-8-flash)

## 如以后决定启用

先保留 `local_complete`，另复制为新的混合 profile，只修改 `model_provider`/`model_name` 和 chat/structured 槽位，其他能力保持本地。示意配置如下，当前未写入真实配置：

```json
{
  "model_provider": "dashscope",
  "model_name": "qwen3.8-flash",
  "model_enabled": true,
  "structured_output_method": "json_schema",
  "model_slots": {
    "chat": {"provider": "dashscope", "model": "qwen3.8-flash"},
    "structured": {"provider": "dashscope", "model": "qwen3.8-flash", "structured_method": "json_schema"}
  }
}
```

这是差异片段：新 profile 还应保留原本的本地 vision/asr/tts 槽位，再填自己的对应地域凭证。不要直接用该片段替换全部 `model_slots`；槽位配置采用整体覆盖。

先对单城、多城、锁定修改、流式和失败重试做小样本 A/B，比较总耗时、有效输出 tokens、费用和业务校验通过率，再决定是否默认使用。保持现有独立测试库，不让测试生成真实预订或修改其他项目。配置可热切回本地；未启用、未实测的云端能力不写成已验收。
