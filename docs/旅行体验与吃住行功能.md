# 中文旅行工作区

参考 [Mindtrip 首页](https://mindtrip.ai/home)和[探索页](https://mindtrip.ai/explore)的导航、分类入口、地点卡片和地图联动方式，在现有 React / FastAPI 项目中实现。界面保持中文，使用本项目名称与图片。

## 主流程

首页以一句话描述旅行开始，进入持续对话；明确条件的用户也可以展开条件表单。生成并保存方案后，桌面工作区显示对话、每日安排、地图三个区域，窄屏切换对话、行程和地图。切换天数、点选地点、查看导航和更换餐厅、住宿都在当前工作区完成。

每天提供四种视图：

- **每日安排**：早餐、游览、午餐、晚餐、住宿和相邻路段放在同一条时间线中。加入实际接驳和缓冲后重新计算建议时间，超时、步行过多和营业时间冲突会提示。
- **吃什么**：查询当天景点周边的具体餐厅，展示菜系、营业时间、地址、电话、评分和地图参考人均（上游提供时）。午晚餐默认避免茶馆、甜品等不适合作为正餐的地点，尽量避免重复餐厅。可查询其他餐厅并替换；菜品与消费详情通过美团实际查询，无法查到时不补写菜单。
- **住哪里**：具体酒店、地址、评分、入住退房日期、晚数、人数、早晚接驳；可查询房型、床型、面积、早餐、取消条件、价格和平台入口。平台脱敏价格原样展示，地图参考消费不当作每晚房价。
- **花费**：逐日和全程费用账单。餐饮、按人票价和公交乘人数，房价按房间数与过夜日计算，退房日不重复计一晚；驾车费用按车辆计，油费和停车费缺失时单列。可填写参考价或确认金额、设置总预算和独立日预算。日均参考额度不等同于独立日预算。缺价项不按零处理，脱敏房价不猜数；未核齐时不能显示“未超预算”。费用与人工核对结果写入新版本，并进入路书。
- **怎么走**：每段路的耗时、步行、参考费用、上下车站点、线路、途经站数及地图导航入口；可切换公共交通、步行、驾车。短距离优先查询步行线路。城际车次和航班单独按出发地、目的地、日期查询，不用市内公交线路代替。

餐厅、酒店和交通选择写入行程新版本，旧版本保留；更新后重新查询相关路段。只读成员不能替换安排。查询资料快照存入 SQL，过期或手动刷新时更新，已查询的吃住行信息进入 Markdown/PDF 路书。

## 其他完整入口

探索支持城市、关键词和地点分类，显示真实来源、地图和详情。收藏支持持久化、分组、备注、移除及带入规划。旅行偏好在新表单和对话中生效。订单与凭证支持住宿、航班、车次、活动的手工记录、编辑和文件关联，确认号与凭证仅创建者可见，不进入公开路书。

## 数据边界

- 高德提供地点与路线；营业资料和交通耗时是查询时参考，不保证未来指定日期的营业或发车情况。
- 美团官方 CLI 提供商品查询原文，界面提取其中实际存在的房型、价格和链接，不推断脱敏数字。班次、房型、菜单和余票取决于上游实际返回；页面不会将“没有查到”显示为已确认。
- 不自动付款或下单，不把选择酒店或记录订单说成已完成预订。
- 合成模式必须主动选择，明确标注，不作为真实接口失败的替代结果。
- 目前以高德支持的国内目的地为主。图片与菜单缺失时显示实际缺口。

## 运行与验证

按项目现有方式直接运行 `run_project.py`；启动器自动执行迁移 `007`—`009`。代码内配置继续作为默认配置入口。

后端覆盖吃住行、候选真实性、版本冲突、权限、收藏、订单、数据导出与账户清理。前端覆盖对话生成、换餐厅/住宿、交通切换、刷新恢复、移动端地图、收藏与订单。实际高德查询及美团房型查询的本地验收结果保存在被忽略的 `reports/` 目录。

## 地点照片

高德图片域名返回 HTTP 地址时，规范化为同一可信域名的 HTTPS 地址，保留原始实景照片。前端遇到第一张失效会尝试该地点的后续照片，全部失败才显示无照片状态，不拿其他景点图片冒充。
