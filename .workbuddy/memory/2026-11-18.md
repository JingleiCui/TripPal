## 修复 PyCharm「Cannot find Python interpreter for this run configuration」
- 根因：项目由 travel_agent 改名为 TripPal 后，PyCharm 2026.1 全局 SDK `Python 3.11 (travel_agent)` 仍注册在
  `$USER_HOME$/PycharmProjects/travel_agent/.venv/bin/python`；`.run/TripPal.run.xml` 的 `SDK_HOME` 展开为
  `$PROJECT_DIR$/.venv/bin/python`（真实 TripPal 路径），两者路径字符串不一致，按路径查不到 SDK。
  历史日志显示 11-17 23:22 旧路径曾真实不存在，IDE 还缓存过无效 SDK；11-18 01:04 软链恢复但会话未重载。
- 修复（先让用户完全退出 PyCharm，避免全局配置被内存状态覆盖）：
  - 全局 `~/Library/Application Support/JetBrains/PyCharm2026.1/options/jdk.table.xml`：该 SDK 5 处 travel_agent
    全部改为 TripPal（name/homePath/site-packages/ASSOCIATED_PROJECT_PATH/PATHS_TO_TRANSFER_ROOT），SDK_UUID 不变。
  - `.idea/tripal.iml` 的 `jdkName`、`.idea/misc.xml` 的 Black `sdkName` → `Python 3.11 (TripPal)`。
  - 全局 trusted-paths 删除旧 travel_agent 条目；IDE 工作区 recent files 中 3 条旧绝对路径改为 TripPal。
  - `.run/TripPal.run.xml` 本身无需改（已经是 `$PROJECT_DIR$/.venv/bin/python`，改完全局 SDK 后自动匹配）。
- 校验：6 个 XML 全部解析通过；全局 SDK homePath 与 run config 展开路径一致；`.venv/bin/python -V` = 3.11.7。
- 保留：`travel_agent -> TripPal` 软链（IDE 工作区仍指向它）；代码包 `backend/travel_agent`、历史 reports/data 日志
  中的旧路径未改（属于模块名/历史记录，不是 IDE 配置）。开放 PyCharm 后需确认解释器显示为 Python 3.11 (TripPal)。
